# Private beta access

The Worker runs before every asset and API (`assets.run_worker_first = true`). `PRIVATE_ACCESS_REQUIRED=true` fails closed without a valid owner secret. Keep all credentials in Worker secrets, never source, browser bundles or reports.

`PRIVATE_ACCESS_CREDENTIALS` retains the existing owner's JSON verifier: `username`, random 16-byte hex `salt`, 32-byte hex PBKDF2-HMAC-SHA256 `hash` (100000 iterations), and random 32-byte hex `signingKey`. The separate optional `PRIVATE_GUEST_ACCESS_CREDENTIALS` has `username`, `salt`, and `hash` in the same format. Guest website access creates no personal identity or role. It still requires personal authentication or human verification for eligible provider operations. Google login and server role checks remain separate.

Unlock issues a hostname-bound, HMAC-signed opaque session with an expiring Durable Object record. Without Remember me, the Secure/HttpOnly/SameSite=Lax cookie has no persistence attribute and the server limit is 12 hours. Remember me sets a seven-day cookie and matching server expiry. Browser session restoration may retain a session cookie; server expiry still applies. Credential rotation changes the verifier epoch. Legacy, tampered, expired and revoked cookies are denied. Lock deletes the server record; replaying a copied cookie fails. Other browser sessions have distinct records.

Settings offers three actions: local personal sign-out keeps website access; Lock website revokes website access; the combined action signs out this device's personal session and locks access. A fresh unlock clears the old stored personal account token before initializing the authentication SDK. An in-progress PKCE verifier and safe callback path/query/fragment are retained. Cross-tab lock and gate changes clear visible account data and reload. Signing out uses `scope: local`, preserving sessions on other devices.

The gate renders one selected language and direction, with a labeled password eye, Remember me and accessible pending/error states. Inline behavior is CSP nonce-authorized. Passwords are same-origin HTTPS form POST only. Five attempts per hashed source IP per ten-minute bucket are permitted. Missing storage fails closed. Wrong credentials receive a generic localized error. Unsafe return targets and foreign-origin POSTs are rejected.

Private responses are no-store. The maintenance-only service worker clears old traffic shell caches and retains generic push handlers; it serves no protected offline shell. `/sw.js` alone is accessible before unlock to purge previous caches. Already displayed content cannot be recalled, but fresh requests are checked. Push receipt still needs actual Android acceptance.

`privatecheck` uses disposable owner/guest fixture credentials generated into an ignored, permission-restricted file. Workerd tests cover protection, expiry, host/origin/tamper checks, Remember me, guest role denial and revocation replay. Browser CI tests exercise desktop and phone entry, language/eye, callback preservation, remembered access in a fresh context, responsive layout and locking. Screenshot artifacts contain synthetic fixtures only. Real owner/guest and Android acceptance remain separate from fixture success.

For recovery, keep private protection enabled and repair forward or use a compatible private version. Never silently roll back to a public build. A rollback to the older private build retains private protection but lacks the new guest/session features, so it cannot be treated as acceptance of this release.
